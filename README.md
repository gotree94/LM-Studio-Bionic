# LM Studio Bionic + 로컬 AI 모델 설치 가이드
## Ubuntu 22.04 LTS / Intel Core Ultra 9 275HX / RTX 5090 Laptop 24GB

- 작성 기준: 2026-10-22
- 대상: Ubuntu 22.04 LTS가 설치된 노트북에서 **LM Studio Bionic** 에이전트와 로컬 LLM을 사용하려는 경우
- 목표: NVIDIA GPU 확인 → Bionic 설치 → 모델 다운로드 → 로컬 추론 확인 → 코딩·문서 작업 에이전트 실습

> **이 문서는 `LM Studio Bionic` 기준입니다.** 이름이 비슷한 오픈소스 서버 플랫폼 `bionic-gpt`와는 다른 제품입니다. LM Studio Bionic은 로컬 오픈 모델을 이용해 코딩, 문서 작성, 조사 등의 작업을 수행하는 에이전트 애플리케이션입니다.
>
> 공식 문서: https://lmstudio.ai/docs/bionic  
> 공식 다운로드: https://lmstudio.ai/download?os=linux  
> 공식 모델 선택 안내: https://lmstudio.ai/docs/bionic/models  
> 릴리스 기록: https://lmstudio.ai/changelog

## 1. 하드웨어와 권장 방향

| 항목 | 사용자 환경 | 의미 |
|---|---|---|
| CPU | Intel Core Ultra 9 275HX, 24코어 / 24스레드 | 전처리, CPU 작업, 일부 CPU 오프로딩 |
| 메모리 | 64GB DDR5-5600 | 모델 외 시스템 작업 및 오프로딩 여유 |
| GPU | NVIDIA GeForce RTX 5090 Laptop GPU, 24GB GDDR7 | 주 추론 장치 |
| NPU | Intel AI Boost, 최대 13 TOPS급 | 일반적인 Bionic LLM 추론에서는 우선 NVIDIA GPU 사용을 권장 |
| OS | Ubuntu 22.04 LTS | Linux x86-64용 앱과 NVIDIA 드라이버 필요 |

### 현실적인 모델 크기

VRAM은 모델 가중치만 차지하는 것이 아닙니다. 컨텍스트의 KV 캐시, 런타임 버퍼, GPU 데스크톱 사용량도 VRAM을 차지합니다. 따라서 모델 파일 크기가 24GB보다 작다고 해서 모든 설정에서 GPU에 완전히 들어간다는 뜻은 아닙니다.

| 용도 | 시작 모델 후보 | 시작 설정 |
|---|---|---|
| 빠른 일반 대화 / 가벼운 작업 | Qwen 계열 8B 모델 | Q4 이상, 컨텍스트 8K |
| 코드 작성·리뷰 | Qwen Coder 계열 14B 또는 지원되는 최신 코딩 모델 | Q4_K_M, 컨텍스트 8K |
| 고성능 에이전트 작업 | Qwen3-Coder 30B-A3B 등 지원되는 MoE 모델 | Q4_K_M, 컨텍스트 8K부터 |
| 복합 추론·문서 작업 | 20B~30B급 모델 | 메모리 사용량을 확인하며 조정 |

**첫 모델 추천:** Bionic의 모델 탐색 화면에서 **Qwen3.8 27B의 GGUF Q4_K_M** 변형이 제공된다면 이를 시험 모델로 선택할 수 있습니다. RTX 5090 Laptop은 데스크톱 RTX 5090과 VRAM 용량이 다르므로, 다운로드 화면의 예상 메모리와 실제 사용량을 반드시 확인하세요. 해당 모델이 표시되지 않으면 지원되는 Q4_K_M 14B급 코딩 모델로 먼저 시작하세요.

모델 이름·태그·지원 형식은 자주 바뀝니다. 모델 목록에 표시되지 않는 이름을 터미널 명령으로 임의 입력하지 말고, Bionic 안의 모델 탐색기에서 실제 제공 여부를 확인하세요.

## 2. 설치 전 시스템 점검

### 2.1 Ubuntu 버전과 CPU 확인

터미널을 열고 실행합니다.

```bash
lsb_release -a
uname -m
lscpu
free -h
df -h /
```

기대 결과:
- Ubuntu 22.04 LTS
- `x86_64` 아키텍처
- 시스템 메모리 약 64GB
- 모델을 저장할 디스크 공간 충분

모델은 수 GB에서 수십 GB까지 차지할 수 있습니다. 모델을 여러 개 보관할 계획이면 모델 파일용으로 최소 100GB 이상의 여유 공간을 확보하는 편이 좋습니다.

### 2.2 NVIDIA 드라이버 확인

```bash
nvidia-smi
```

정상이라면 GPU 이름, 드라이버 버전, VRAM 사용량이 표시됩니다.

문제가 있으면 다음을 확인합니다.

```bash
ubuntu-drivers devices
```

Ubuntu의 권장 드라이버를 확인한 뒤 설치할 수 있습니다.

```bash
sudo ubuntu-drivers autoinstall
sudo reboot
```

재부팅 후 다시 확인합니다.

```bash
nvidia-smi
```

> 주의: 이미 정상 동작하는 NVIDIA 드라이버가 있다면 무조건 재설치하지 마세요. 노트북 제조사 설정, Secure Boot, 커널 버전과 호환성을 확인한 뒤 변경합니다. 일반적인 Bionic GUI 사용에는 별도로 CUDA Toolkit을 설치할 필요가 없는 경우가 많습니다. 먼저 공식 앱이 제공하는 추론 런타임을 사용하세요.

### 2.3 기본 패키지 설치

```bash
sudo apt update
sudo apt install -y curl wget ca-certificates git pciutils build-essential
```

GPU가 보이지 않는 경우 PCI 장치 확인:

```bash
lspci | grep -Ei 'vga|3d|nvidia'
```

## 3. LM Studio Bionic 설치

### 3.1 공식 배포판 확인

공식 다운로드 페이지를 엽니다.

- https://lmstudio.ai/download?os=linux

Bionic과 일반 LM Studio는 **서로 다른 애플리케이션**입니다. 다운로드 페이지에서 Bionic용 Linux 빌드가 제공되는지 확인하고, `Linux x64` 또는 이에 해당하는 빌드를 선택하세요. 릴리스 기록에는 Bionic Linux 지원 여부와 수정 사항이 게시됩니다.

- Bionic 안내: https://lmstudio.ai/docs/bionic
- 릴리스 기록: https://lmstudio.ai/changelog

**중요:** 다운로드 페이지의 버튼·패키지 형식은 업데이트될 수 있습니다. 실제 페이지에 표시되는 Linux용 Bionic 패키지를 기준으로 설치하세요. macOS 또는 Windows용 설치 파일을 Ubuntu에서 실행하지 마세요. 공식 Linux Bionic 패키지가 보이지 않는 경우에는 임의의 비공식 설치 스크립트를 사용하지 말고, 공식 릴리스 페이지에서 Linux 지원 버전을 확인하세요.

### 3.2 AppImage를 받은 경우

파일을 다운로드한 디렉터리에서 파일 이름을 확인합니다.

```bash
ls -lh
```

공식 다운로드 페이지에서 받은 파일이 실제로 `.AppImage`인 경우에만 아래 절차를 사용합니다.

```bash
sudo apt install -y libfuse2
chmod +x ./Bionic*.AppImage
./Bionic*.AppImage
```

파일 이름이 패턴과 다르면 실제 파일 이름을 사용하세요. 배포 패키지가 `.deb` 또는 다른 형식이라면 해당 형식에 맞는 공식 지침을 따릅니다. `.deb` 패키지라면 예를 들어:

```bash
sudo apt install ./다운로드한_공식_패키지.deb
```

위의 파일명은 예시이므로 실제 다운로드한 이름으로 바꿔야 합니다.

### 3.3 첫 실행

1. Bionic 앱을 실행합니다.
2. 온보딩 화면을 따라 초기 설정을 완료합니다.
3. 새 프로젝트를 만듭니다.
4. 새 세션을 열고 모델 선택기(Model picker)를 찾습니다.
5. `Local` 모델을 선택합니다.
6. 아직 모델이 없다면 모델 탐색 화면에서 로컬 모델을 다운로드합니다.

Bionic의 로컬 모델은 컴퓨터에서 추론을 수행합니다. 클라우드 모델은 원격 서버에서 실행되며, 원격 모델은 LM Link로 연결한 다른 장치에서 실행됩니다. **완전한 로컬 사용을 원한다면 세션의 모델 선택기가 `Local`인지 확인**하세요.

## 4. 첫 로컬 모델 다운로드

### 방법 A — Bionic 내부에서 다운로드 (권장)

1. Bionic에서 새 프로젝트 또는 세션을 엽니다.
2. 모델 선택기를 엽니다.
3. `Local` 또는 로컬 모델 탐색 메뉴로 이동합니다.
4. 모델 검색창에 `Qwen3.8 27B`, `Qwen Coder 14B` 등 모델명을 입력합니다.
5. 지원되는 형식 중 `GGUF`를 선택합니다.
6. 우선 **Q4_K_M** 양자화를 선택합니다.
7. 다운로드가 끝나면 해당 모델을 세션의 모델로 지정합니다.
8. 아래의 테스트 프롬프트를 실행합니다.

Q4_K_M은 메모리 사용량과 품질의 균형을 위한 일반적인 출발점입니다. Q8이나 더 높은 정밀도는 품질에 유리할 수 있지만 VRAM을 훨씬 더 사용할 수 있습니다.

### 첫 테스트 프롬프트

```text
한국어로 답변해 줘.
이 세션에서 사용하는 모델 이름과 로컬 모델인지 여부를 알려줘.
간단한 Python 코드 리뷰를 수행할 때 어떤 정보를 먼저 확인해야 하는지
체크리스트 5개로 작성해 줘.
```

답변이 생성되면 로컬 추론의 기본 동작을 확인한 것입니다. 단, 화면에서 모델 이름만 확인하는 것보다 세션의 실행 위치가 Local로 설정되어 있는지도 함께 확인하세요.

## 5. RTX 5090 GPU가 실제로 사용되는지 확인

Bionic에서 모델 응답을 생성하는 동안 별도의 터미널에서 실행합니다.

```bash
watch -n 1 nvidia-smi
```

확인할 항목:
- GPU 메모리 사용량이 증가하는가?
- GPU 사용률이 작업 중 증가하는가?
- 모델이 실행되는 동안 관련 프로세스가 보이는가?

종료는 `Ctrl+C`입니다.

GPU 사용률이 항상 높아야 정상인 것은 아닙니다. 프롬프트 처리와 토큰 생성 단계에 따라 사용률이 달라집니다. 작업 전후 VRAM 변화와 응답 동작을 함께 보세요.

Bionic 또는 런타임의 모델 상세/고급 설정에서 다음을 확인할 수 있다면 점검합니다.
- GPU offload 또는 GPU 사용 설정
- Context length
- KV cache 관련 설정
- 모델 로딩 상태와 메모리 요구량

설정 이름은 버전에 따라 달라질 수 있으므로, 존재하지 않는 메뉴를 찾기보다 현재 버전의 UI와 공식 문서를 기준으로 합니다.

## 6. 컨텍스트 길이와 메모리 튜닝

처음에는 컨텍스트를 **8K(약 8,192 토큰)** 정도로 시작합니다. 모델이 안정적으로 실행되고 VRAM 여유가 있으면 16K 등으로 늘려 테스트합니다.

컨텍스트를 늘리면 긴 소스 코드와 문서를 다루기 편해지지만 KV 캐시가 커져 VRAM 사용량도 증가합니다. 큰 모델과 긴 컨텍스트를 동시에 선택하면 모델이 로딩되지 않거나 일부 작업이 느려질 수 있습니다.

권장 순서:

1. Q4_K_M 모델 + 8K 컨텍스트로 시작
2. 간단한 질의와 짧은 코드 작업 수행
3. `nvidia-smi`로 VRAM 사용량 확인
4. 메모리 여유가 충분하면 컨텍스트를 단계적으로 증가
5. 로딩 실패나 메모리 부족이 생기면 컨텍스트를 낮추거나 더 작은 모델 선택

64GB 시스템 RAM은 일부 데이터를 CPU 메모리에 두는 데 도움이 되지만, CPU 오프로딩은 GPU에 완전히 올리는 것보다 느릴 수 있습니다. 노트북에서는 전원 어댑터를 연결하고 냉각 상태를 확인한 상태에서 비교하세요.

## 7. Bionic 에이전트로 실제 작업하기

Bionic은 단순 채팅뿐 아니라 프로젝트 단위로 코딩과 문서 작업을 수행하도록 설계된 에이전트입니다. 모델이 도구 호출을 지원하는지, 해당 작업에서 필요한 도구가 활성화되어 있는지도 중요합니다.

### 7.1 개발 프로젝트 만들기

예를 들어 다음과 같은 디렉터리를 만들 수 있습니다.

```bash
mkdir -p ~/AIProjects/bionic-lab
cd ~/AIProjects/bionic-lab
git init
```

Bionic에서 이 디렉터리를 프로젝트로 열 수 있다면 프로젝트 작업 공간으로 지정합니다. 앱이 디렉터리 선택을 지원하지 않는 버전이라면 프로젝트 생성 UI의 안내를 따르세요.

### 7.2 첫 코딩 작업

```text
현재 프로젝트의 파일 구조를 먼저 살펴봐.
파일을 수정하기 전에 무엇을 변경할지 계획을 제시해 줘.
그 다음 Python으로 간단한 CSV 데이터 검사 도구를 만들고,
README.md와 실행 예제를 작성해 줘.
파일을 수정하거나 명령을 실행하기 전에는 필요한 경우 승인을 요청해.
```

### 7.3 하드웨어 개발 프로젝트용 프롬프트

```text
이 프로젝트는 Ubuntu 22.04에서 개발하는 임베디드/FPGA 실습 저장소야.

작업 원칙:
1. 기존 파일을 먼저 읽고 구조를 요약한다.
2. 수정 계획을 먼저 제시한다.
3. 기존 코드를 삭제하거나 대규모 변경하기 전에 확인을 요청한다.
4. Verilog 코드가 필요하면 기본적으로 Verilog-2001 이하의 호환성을 고려하고,
   SystemVerilog 문법을 쓸 경우 명시한다.
5. 테스트 명령과 예상 결과를 README.md에 기록한다.
6. 확인하지 않은 테스트를 성공했다고 주장하지 않는다.

먼저 저장소를 분석하고 개선 제안서를 작성해 줘.
```

### 7.4 도구 권한과 보안

에이전트가 파일을 편집하거나 셸 명령을 실행할 수 있는 경우 다음 원칙을 지킵니다.

- 처음에는 읽기 전용 분석과 계획 수립부터 시험합니다.
- `sudo`, 시스템 설정 변경, 패키지 삭제, 파일 대량 삭제는 직접 검토합니다.
- 개인 키, 토큰, 비밀번호가 있는 파일을 프로젝트 폴더에 넣지 않습니다.
- Git 커밋 또는 백업을 만든 후 중요한 변경을 허용합니다.
- 출처를 알 수 없는 MCP 서버나 플러그인을 무조건 활성화하지 않습니다.
- 인터넷 접근이 켜져 있으면 로컬 모델을 사용하더라도 도구가 외부에 접속할 수 있는지 별도로 확인합니다.

로컬 추론은 모델 입력을 외부 추론 서버로 보낼 필요를 줄여주지만, 에이전트 도구·웹 검색·외부 API가 실행되면 해당 데이터가 기기 밖으로 나갈 수 있습니다.

## 8. 문제 해결

### `nvidia-smi`가 동작하지 않음

```bash
nvidia-smi
ubuntu-drivers devices
lspci | grep -Ei 'vga|3d|nvidia'
```

드라이버 설치 상태, Secure Boot, 커널 업데이트 후 드라이버 모듈 상태를 점검합니다. 정상 드라이버를 불필요하게 제거하지 마세요.

### 앱이 실행되지 않음

AppImage인 경우에만 다음을 확인합니다.

```bash
file ./다운로드한_파일.AppImage
chmod +x ./다운로드한_파일.AppImage
```

실행 로그를 확인하려면 터미널에서 실행합니다.

```bash
./다운로드한_파일.AppImage
```

파일 형식이 AppImage가 아니라면 이 명령을 사용하지 말고 해당 패키지 방식에 맞는 실행 절차를 따릅니다.

### 모델 다운로드는 됐지만 로딩에 실패함

- 더 작은 양자화 또는 14B급 모델을 선택합니다.
- 컨텍스트 길이를 8K로 낮춥니다.
- 다른 GPU 작업과 브라우저의 GPU 사용을 줄입니다.
- 다음 명령으로 메모리 상태를 확인합니다.

```bash
free -h
nvidia-smi
df -h
```

### 응답이 느림

- 모델이 실제로 Local로 실행되는지 확인합니다.
- GPU 메모리와 GPU 사용량을 확인합니다.
- 컨텍스트 길이를 낮춰 비교합니다.
- 노트북 전원 모드와 냉각 상태를 확인합니다.
- 모델 크기와 양자화가 현재 VRAM에 적합한지 확인합니다.

### 모델 이름을 찾을 수 없음

모델 레지스트리의 이름과 태그는 변경될 수 있습니다. Bionic의 모델 탐색 화면에서 실제로 제공되는 이름을 확인하고, 비슷한 이름의 모델을 임의로 가정하지 마세요.
